## Project Overview

Website for a **Leadership Coach** specializing in clarity and decision-making under pressure.

**Positioning:** Helps leaders and senior experts in international organizations (Amazon, Google, BMW, Booking, Vodafone, Facebook, Swedbank, etc.) regain decision-making capacity and clarity before pressure becomes unsustainable. 1:1 coaching only.

**Brand pillars:** Clarity · Precision · Structured thinking · Safety through confidence · Scientific approach

**Tone:** Professional, precise, grounded in real business constraints. No generic frameworks, no motivational fluff. The work starts from seeing the problem clearly.

**Credentials:** 19+ years in HR, ICF & EMCC certified coach (ACC), certified corporate trainer, working across Europe, UK, and CIS.

See `temp/BRIEF.md` for full positioning details.

## Stack

- **React 18** + **React Router 6** (`react-router-dom`), JSX in `src/`, bundled by **esbuild** into `assets/app.js`
- **Prerendered**: every route is rendered to static HTML at build time (`StaticRouter` + `renderToString`), then hydrated in the browser with `hydrateRoot` + `BrowserRouter`. Content is visible without JS; real URLs, deep links, refresh and Back all work.
- **Tailwind CSS 3** compiled from `src/tailwind.css` to `tailwind.css`. Design tokens (colors, fonts, max-width, radii) live in `tailwind.config.js`; shared component classes (`.shell`, `.btn`, `.t-*` type scale, `.tag`, `.section*`, …) are in `@layer components` in `src/tailwind.css`.
- **Google Fonts**: Cormorant Garamond (serif, headlines), Material Symbols Outlined (icons)
- **Local font**: Pragmatica Book (sans-serif, body) — self-hosted via `fonts/Pragmatica_Book.css`
- Hosting: **GitHub Pages** from the `main` branch root (custom domain via `CNAME`, `.nojekyll` so files are served as-is). There is no CI build — generated files are committed.

## Workflow

1. Edit files in `src/` (and `tailwind.config.js` / `scripts/` if needed). Never edit generated files by hand.
2. Run `npm run build`.
3. Commit the source **and** the generated files. GitHub Pages serves the repo root.

npm scripts:

| Script | What it does |
|--------|--------------|
| `build` | `build:css` → `build:js` → `build:html` |
| `build:css` | Tailwind: `src/tailwind.css` → `tailwind.css` (minified; content globs `./src/**/*.{jsx,html}`) |
| `build:js` | esbuild: `src/client.jsx` → `assets/app.js` (minified IIFE, es2018, production React) |
| `build:html` | `scripts/prerender.mjs`: renders each route into `src/template.html`, writes `<route>/index.html` and `sitemap.xml` |
| `preview` | `build`, then `scripts/preview.mjs` serves the repo root at http://localhost:5173 (opening `index.html` via `file://` breaks — asset paths are absolute) |

## Architecture

- **Common components**: `NavBar` (scroll-aware background, mobile menu, active link underline), `Footer` (Impressum link), `ScrollToTop`, `DocumentTitle` (syncs `<title>` on client navigation)
- **Pages**: `HomePage` (incl. case accordion), `AboutPage`, `ContactPage`, `ImpressumPage`
- **Routing**: `routes` in `src/App.jsx` → `Routes` / `Route`. Paths use trailing slashes — `/`, `/about/`, `/contact/`, `/impressum/` — matching how GitHub Pages serves `about/index.html` (it redirects `/about` → `/about/`). Use the trailing-slash form in `Link`/`navigate` targets; `NavBar` compares active state in that form.
- To add a page: create it in `src/pages/`, add an entry to `routes` (path with trailing slash, title, description), run `npm run build`. The prerender script picks it up and adds it to the sitemap.
- All asset paths are absolute (`/tailwind.css`, `/images/…`, `/assets/app.js`) because pages live in subfolders.
- Hydration must stay clean: render output must not depend on `window` or other browser-only state — read those in `useEffect`.
